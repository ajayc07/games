# Task 037: Cave world, the map branch and the first Cave level

Design: D-085. Read D-002, D-036, D-039, D-060, D-080, D-082 and D-085 first. Lifts the feature freeze (D-077) for Tasks 037-040 only.

## Goal
A second world, **Cave**, that he reaches from a clearly visible **branch** on the Grass map, with its own look (dark-blue rock, glowing crystals) and first level `cave-1`. He has outgrown Grass 1-3; the Cave is the next stage.

## Read first
- CLAUDE.md, docs/PROGRESS.md, docs/DECISIONS.md, docs/architecture/map-and-flow.md, docs/architecture/levels.md.
- `universes/robo/{manifest.ts,worlds.ts,themes.ts}`, `core/map/{MapScene,mapLayout,unlock}.ts`, `core/levels/placeholders.ts`, `ParallaxBackground` (the night theme is the template for a second theme).

## In scope
- **World data:** a `cave` world in `worlds.ts` (levels `cave-1` ..., more added by 038-040) and a `caveTheme` in `themes.ts`: rock ground, dark-teal backdrop with parallax stalactites and cave arches, glowing crystals, a few drifting glow-motes. Avatar, bubbles, coins and orbs must stay readable; all eight robot colours visible. Code-drawn only. Nothing may be hidden by darkness.
- **The branch (the main design point):** on the Grass map the path forks at the end of Grass 6: one branch runs on to Grass 7 and the other levels as now, the second goes into a big glowing **cave mouth** (a rock arch with crystals, about 2x a dot, hit target 170 px or more). It is visible from the start of the map's right end so he sees it coming. Tapping it hops the robot in and opens the Cave map (a fade through the dark). The Cave map has a matching meadow arch at its left end that goes back. While locked the mouth is covered by a boulder that shakes with a soft bump when tapped; it opens after Grass 6 is cleared (data: `unlock: { afterLevel: 'grass-6' }`). `?unlock=all` opens it.
- **Parent view:** a row "Open the Cave now" (page 1, next to Unlock all) that sets a saved flag so he can go in at once. Kept on a progress reset (like colour and settings).
- **Generality:** map, unlock rule and branch come from world data, not from "grass" or "cave" strings in `core/`. `currentDot` and the arrival animation must work across two worlds; one progress record, per-world star totals.
- **Level `cave-1` "Cave Walk":** gentle intro, no enemies, about 70 tiles, all four buttons, crystal-look coins, a few small bubbles, two small gaps. Stars by coins. No demo.
- Teasers after the Cave: Sky and Castle.
- Docs: `map-and-flow.md` (branch, world switch), `levels.md`, `PROGRESS.md` (roadmap, hooks, tablet checklist: does he see and tap the mouth, understand the way back, is the cave readable), this file's Result.
- One commit: `task-037: cave world, map branch and cave-1`. No attribution. Do not push. No dev server left running.

## Result
- What changed: A second world, the Cave, reached from a big glowing rock mouth above the Grass path just after Grass 6 (a 180 px tap square). While locked a boulder covers it and only shakes when tapped; after Grass 6 has a star (or with `?unlock=all`, or the parent's new "Open the Cave now" row) the boulder rolls away in the arrival animation and a cyan halo breathes. Tapping the open mouth: the robot hops to it in one long arc, hops in, and the screen fades through dark blue to the Cave map (cave-1, Sky and Castle teasers, a green meadow arch at the left end that fades back and puts him at the fork dot). Cave look generated in code (stalactites, floor crystals, drifting glow-motes, dark-blue rock, crystal-cyan coins). New level `cave-1` "Cave Walk" (72 tiles, four buttons, two gaps with coin arcs, 29 coins, 5 small bubbles, stars 18/34). Map, unlock and branch come from world data (`WorldDef.branchFrom`, `.unlock`), nothing in `core/` names a world.
- Files touched: `core/types.ts`, `core/map/{unlock,mapLayout,MapScene}.ts`, `core/levels/{theme,placeholders,background}.ts`, `core/parent/{ParentScene,parentLayout}.ts`, `core/storage/{progress,store}.ts`, `universes/robo/{worlds,themes,manifest}.ts`, new `universes/robo/levels/cave-1.json`; tests `core/map/branch.test.ts` (new), `universes/robo/levels/levels.test.ts`, `core/storage/progress.test.ts`; docs `PROGRESS.md`, `architecture/{map-and-flow,levels}.md`, this file.
- Deviations from plan (and why): (1) The task named `unlock: { afterLevel: 'grass-6' }`; I added `branchFrom: { world, fork }` beside it so the map knows where the path forks, and the parent flag is a generic `ProgressRecord.openedWorlds` list (not a `caveOpen` boolean). (2) The mouth stands above the path (centre y 245) just right of the fork dot rather than on a literal fork of the line: a side path joins them. (3) The cave hills are pale "lit rock", not dark: a dark hill fails the 3:1 contrast of the robot's dark joints (orange failed at a darker blue), exactly as the night hills; the dark feeling comes from the sky, stalactites, ground and fade. (4) The coin is a pale cyan crystal, not the gold coin: the one visual risk is that it reads less like "a coin" to him; the hex-nut face is kept. (5) The robot's hop to the mouth is one long arc (not dot by dot over possibly locked dots). (6) The mouth hosts `stars` totals (`worldStars`) in its data for the later crowns but shows nothing yet. (7) Teasers are now Sky and Castle on both maps (the Cave teaser left the Grass map because the Cave is a branch). (8) The Cave row is a seventh row on parent page 1; it still fits at all sizes (tested, also with notch insets). (9) Left uncommitted on purpose: the architect's pending edits to `docs/ARCHITECT_HANDOFF.md` and `docs/DECISIONS.md` (D-086 etc.); `docs/PROGRESS.md` already carried the architect's one-line change and is in this commit.
- How verified: `npm run typecheck`, `npm test` (all pass: 45+ files, new tests for branch unlock, layout at five sizes, record round trip and reset, the parent row fit, cave look contrast for all eight colours, cave-1 structure and a bot on the written grid and 200 varied grids) and `npm run build`; banned-names test passes, no image files. In Chromium (Playwright, headless software GL, 10-30 fps) at 844x390 and 1280x800: locked mouth with boulder (tap = shake, stays on the Grass map), open mouth, tap -> hop -> fade -> Cave map (1 dot, arch, 2 teasers), tap the arch -> Grass map with the robot on the fork dot; cave-1 played in red, teal and purple at both sizes; the parent row turned On, saved, a fresh visit shows the mouth open without `?unlock=all`. No console or page errors. Sheets in `_sources/review/037/` (not committed).
